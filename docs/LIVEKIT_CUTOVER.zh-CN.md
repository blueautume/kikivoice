## 独立运维应用

应用顶部分别选择 **语聊服务 · furby.top** 和 **账号服务 · kiki.group**。每台服务器使用独立管理口令和最长 8 小时的只读会话；口令本身不保存，不会把一个口令自动发送给两台主机。两套会话分别存入 Keychain，切换时清除当前快照、取消刷新并丢弃旧服务迟到的响应；后台暂停刷新并遮罩页面。

| 看板 | 当前统计口径 |
| --- | --- |
| 语聊 | 活动房间、入场名额与 SFU 实际在线人数、语聊参与身份、信令连接与质量样本、该语聊主机资源、媒体/API 服务和证书 |
| 账号 | 总账号/今日新建、有效业务会话及持有有效会话的账号、今日新建且仍有效会话的账号、保存 Apple 授权凭据的账号、Apple 待撤销队列、自定义头像与文件/数据库占用、该账号主机资源、API 服务和证书 |

有效业务会话可能来自离线设备，不代表在线人数或 DAU；语聊参与身份也不等于账号 DAU。两个看板不会拼接主机 CPU 或网络数据。语聊响应中的 `accountService.connected=false` 表示该响应不含账号指标，并不表示运维 App 无法连接独立账号看板。账号 API 只返回汇总数，不返回 Apple subject、邮箱、刷新令牌、账号明细或头像文件清单。

管理认证目前仍使用口令，本期不接入 Apple 管理登录，也不提供强制结束房间、封禁等管理写操作。API 合约分别见 [语聊管理合约](../experiments/livekit/shared/admin-api-contract.json) 与 [账号管理合约](../experiments/livekit/shared/account-admin-api-contract.json)。

## 停机发布与回滚概要

1. 确认仅处理上述两台主机，停止账号及语聊 API 的新业务写入，确认活动媒体房间与待清理任务后记录状态。受限备份必须包含各自一致的 SQLite/头像、程序、环境配置、systemd/Nginx 配置和当前协议；两个服务分别记录恢复路径。
2. 发布账号桥接和独立管理 API；发布语聊 `account` 模式、相同的独立桥接秘密和新的正式协议。启用内部接口访问限制与管理接口 `no-store`/日志边界，公共证书副本只用于到期采样。
3. 不将旧业务数据并入新库。实际清理、Apple 授权待撤销处理和备份保留情况按发布记录逐项核对；不把自有在线库清理表述为腾讯云历史数据或备份已全部删除。
4. 恢复服务，检查两个域名 HTTPS、API 健康、内部交换认证、无邀请码登录、账号/语聊/管理令牌隔离、64 名额保护与正常退出/撤回/注销清理。账号服务恢复前应保证对应版本的语聊服务可接收其授权。
5. 发布并安装新的 KikiTalk 构建，旧安装包不继续联通腾讯语聊；运维 App 分别使用各自口令登录。最后完成下列人工真机场景。

发生需回滚的问题时，先停止两端 API 并退出活动媒体，分别恢复同一切换批次的程序、配置、数据库和头像，再按恢复版本启动服务并验证。账号桥接和语聊认证模式必须匹配，不能只恢复一台机器。新版本开始产生数据后，直接回灌旧库会丢失新写入，必须先保留新状态再明确选择恢复批次；备份中待撤销的旧授权不能未经核对重新启用。客户端与协议版本也需同批处理，恢复腾讯旧服务还需旧 SDK/服务配置确实可用，不代表具备自动热切回能力。

离线 fixture、ASGI 跨服务测试、模拟器和公开接口验收不能替代本人真实 Apple 授权或听感。本轮切换后的下列场景仍需在签名真机操作，并由执行者记录结果：

## 后台连麦与授权续期（2026-10-20）

应用进入后台不等同于离房。当前音频和信令连接健康时，房主与成员保持在线、角色及麦位；已开启的语音会话继续运行，手动静音不因切回前台或恢复连接而自动开启。只有服务端确认真实断联后，才启动房主 15 秒、成员 60 秒的原有重连宽限；主动离房仍立即处理，房主主动结束仍关闭房间。授权到期、撤销、禁麦和系统音频打断继续按既有安全规则处理。

客户端原先在定时续期、回到前台和重连恢复时，将一次临时 HTTP 或网络失败直接作为会话失效，从而停止媒体并退房。本轮改为：现有授权尚未过期且错误为临时网络、超时、限流或服务暂不可用时保留会话；定时续期在正常间隔与 5 秒的较小值后重试，等待不超过现有授权剩余期限。明确失效、身份或协议错误不会据此延长授权。房间轮询每轮读取当前凭据，迟到的旧令牌 401 只触发重新同步，不能使更新后的会话失效。取消的旧重连任务也不能关闭新任务的音频或覆盖其安全状态。

后台音频能力原已启用，本轮未添加静音保活或额外采集。随包 `UIBackgroundModes` 包含 `audio`；固定 LiveKit Swift 2.18.0 的后台处理仅暂停摄像头视频，音频会话按实际播放和采集管理。必要授权续期和房间连接维护不受页面的前台刷新开关控制。

服务端原有在线判定使用真实 SFU 和已验证的信令连接，并不要求客户端持续刷新 REST 页面。账户与语聊续期原地延长同一会话，正常续期不需要重建信令连接。新增回归通过模拟时间推进验证：10 分钟不发 REST 请求仍保持房主和成员在线及麦位；实际信令断开后，无 REST 请求也按 15 / 60 秒回收；真实签名 bridge 续期后跨过首次 15 分钟期限，原信令对象、会话哈希、麦位与音频权限仍有效。没有修改或重发后端生产代码。

## 刷新边界与房间目录即时失效（2026-10-20，本地待发布）

本轮按用户要求只在模拟器与本地后端验证，版本升级为 1.0.6（3），不安装、启动或操作真机，不部署生产服务。计划及边界为：稳定房间布局；将同一房间的数据读取收敛到 RTC 生命周期；用持久目录修订提示新开／关闭房间；私聊另由账号服务权威执行首次联系限额。未引入新的消息权威或第三方通信服务。

### 界面稳定

房主、麦位、成员和上麦申请取消可见的重连文案，恢复时不插入额外提示行；离线头像置灰，保持原占位尺寸与顺序。辅助功能仍能识别离线。开房入口为原生麦克风胶囊按钮，高 44 点、宽高比 1.6，渐变边缘光与两次有限扫光；隐藏页面、切后台、禁用或系统减少动态效果时取消动画。

相同的房间、成员、消息、礼物、钱包和外观快照不重复发布。后台式数据刷新保留当前内容，不反复显示 loading 或禁用输入；真正的写操作和权限变化仍能禁用对应控件。消息首页首屏刷新与分页共用一个读取入口，等待中的刷新／分页各保留一次后续操作，避免乱序覆盖页面。

### 房间内刷新

状态、聊天与礼物由一个 RTC 驱动拥有，视图仅报告可见性。驱动的 1 秒本地调度不表示每秒发 HTTP；各资源各有下一允许时间，正常补偿间隔统一为 12 秒。聊天提交后的服务端提示、SDK 成员与权限变化、成功房间操作以及 HTTP 礼物回执触发资源失效并读取权威 HTTPS 数据。提示只携带版本和资源名，不能提供成员身份、消息正文、余额或权限；大小与资源白名单检查、合并节流、尾随读取及失败退避限制异常提示的影响。

已有旧请求不能代表它开始之后发生的事件：失效提示到达时，旧读完成后还需一次后续读取。安全状态由服务拥有的单一任务读取，以生命周期、黑名单变更和账号隐私代次隔离旧响应；页面取消不会取消通话安全读取，真实失败仍暂停音频。举报列表独立读取，列表失败不影响媒体安全状态。黑名单仍每 15 秒补偿，钱包／外观为 60 秒，网络指标为 10 秒；显式操作可立即失效。退出、撤回或账号切换取消旧资源任务。旧客户端不发送新状态／礼物提示，或发送方无 Data 权限时，以最长 12 秒正常补偿恢复；关闭房间与 SDK 撤权仍通过连接事件及时处理。

### 房间目录

旧实现主要靠应用根视图每 20 秒读取完整房间列表。现在仅当目录真正可见、应用在前台且房间未覆盖时，等待 `/v1/room-catalog/changes`；初次读取修订后获取列表，随后使用 `waitSeconds=15` 长请求，修订变化才再读完整列表。房间创建／删除、状态及标题／分类／主题变化通过 SQLite 纯 SQL 触发器递增持久修订；提交后进程事件唤醒等待者。等待不持数据库锁、不访问 SFU；每进程只有一个 5 秒低频修订探测，覆盖外部数据库写入，未放开既有单 worker 业务约束。

客户端不能把观测修订之前已经在途的旧 GET 当作新版列表，必须完成一次观测之后的读取再确认修订。人数和成员预览属于列表快照，另外保留 60 秒完整读取补偿，不新增计时器。旧服务不支持目录端点时，本会话只探测一次，然后降级为可见页面每 15 秒静默读取；429 与网络错误按服务端要求或指数退避。手动刷新与目录读取合并，取消／换账号后的响应不应用。房间展示状态只转发一个变化信号，收起房间后目录恢复订阅，不桥接所有 RTC 高频状态。

目录修订只用于失效，`GET /v1/rooms` 继续提供经过认证和 SFU 核对的房间卡片；服务端关闭与权限处理不依赖提示发布成功。验收与日志位于 `experiments/livekit/validation/stable-refresh-dm-2026-10-20/`。截图使用隔离的生产组件 fixture，不能当作实际多人通话或真机收音验收；最终测试数量见该目录的验证汇总。

最终 iPhone 与 iPad 模拟器各 255 项主回归通过，0 失败、0 跳过。截图检查后补齐等待回复时发送按钮的禁用外观；最终源码再次通过两端各 16 项私聊相关补验（iPhone 分 11＋5 项运行，均为主回归中的子集，不额外计为新用例）。模拟器实际安装包为 1.0.6（3），保留 `audio` 后台模式及相机用途声明。20 张组件截图位于 `output/stable-refresh-dm/`；原生输入权限已检查，SwiftUI Send 按钮未自动点击，不将截图称为真实私信发送验收。两次早期构建的类型约束和只读环境键测试配置错误已修正，原日志保留；最终构建与用例均通过。
