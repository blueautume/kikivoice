# KikiTalk 商业版功能与投入大纲

面向投资沟通 · 2026-10-16 · 金额均为人民币预算估算

**定位：面向中国大陆的中文语聊与直播社区，覆盖 iOS、Android、原生鸿蒙；首发包含充值、礼物、会员。** 主界面延续“语聊/直播”和“我”，私聊与通知可从消息入口进入。后台支持平台经营、内容治理和资金管理。

## 1. 产品全景与建设原则

三端 App + Web 管理台 → 自有业务后台 → 自有数据库、文件存储与备份；业务后台同时连接腾讯实时音视频/IM、审核、推送及支付渠道。

![整体模块图](../output/diagrams/kikitalk-commercial-overview.svg)

- **自建核心资产：** 用户与关系、订单与账本、会员权益、举报处罚、运营配置及经营数据。关键记录保存在自己的业务系统。
- **复用成熟服务：** 音视频、即时通信、机审、厂商 Push、支付、托管数据库、对象存储与安全防护，减少底层研发投入。
- **当前进度：** 已有 iOS 可用原型、自有基础后台和真实腾讯实时互动接入；具备八麦房间、昵称/相册头像、资料、收藏/历史、应用内悬浮恢复。Android、原生鸿蒙、支付闭环、完整治理与经营后台尚需建设。当前基础不等于商业版已完成。

## 2. 按优先级划分的功能模块

🔴 **P0 核心模块：公开运营或收费前完成。** 🟠 **P1 必要模块：首个完整商业版本配齐。** 🔵 **P2 重要模块：根据经营和规模投入。** 优先级表示投入顺序，不表示对已开放功能可以降低安全要求。

| 优先级 | 模块 | 对投资人的功能说明 |
| --- | --- | --- |
| 🔴 P0 | 三端客户端 | iOS、Android、原生鸿蒙；统一账号与资产、房间互通、权限、后台音频、弱网恢复、版本升级 |
| 🔴 P0 | 账号与“我” | ID 登录和账号恢复、昵称/头像、个人资料、钱包/会员、设置、隐私与注销；预留后续 Apple 登录 |
| 🔴 P0 | 语聊与直播 | 房间发现/创建、八麦上下麦、房主/房管、禁言踢人、公告与弹幕、视频直播、最小化返回 |
| 🔴 P0 | 充值、礼物、会员 | 商品、支付验单、钱包/账本、送礼与权益、订阅/到期、退款、对账与交易通知 |
| 🔴 P0 | 内容安全与反作弊 | 文本/图片/音视频机审、人工巡检、反骚扰反诈骗、异常充值/消费、未成年人保护 |
| 🔴 P0 | 举报、封禁、申诉 | 房间/用户/消息举报、证据留存、分级处罚、禁言/封号/关房、申诉复核及跨端生效 |
| 🔴 P0 | 基础管理台与客服 | 用户/房间/商品/订单查询、审核处置、退款与投诉受理、角色权限、敏感操作审批与审计 |
| 🔴 P0 | 合规与可靠运行 | 隐私/协议/备案及适用资质、账号数据权利；服务器安全、监控告警、备份恢复、支付和故障应急 |
| 🟠 P1 | 社交与消息 | 关注/粉丝、收藏/历史、私聊会话及文本/图片/语音消息、未读、屏蔽、陌生人准入 |
| 🟠 P1 | 通知与 Push | 系统/互动/交易/处罚通知中心；APNs、Android 厂商和鸿蒙推送，免打扰、频控和消息跳转 |
| 🟠 P1 | 日常运营中心 | Banner/公告、房间推荐与分类、活动配置、主播管理、客服工单、内容审核队列和质量复核 |
| 🟠 P1 | 经营分析与版本质量 | 活跃/留存、付费转化、收入/退款、房间质量、举报率、单位用户成本；崩溃与音视频质量看板 |
| 🔵 P2 | 增长与增值体验 | 邀请归因、优惠活动、装扮勋章、会员分层、主题活动、规则推荐与实验 |
| 🔵 P2 | 主播/公会经营 | 招募、认证、合同、排班、收益工作台、公会管理；若开放现金收益，结算/提现/税务与资金风控提前升为 P0 |
| 🔵 P2 | 容量与效率升级 | 自动扩容、热点缓存、数据仓库、高级反作弊、多地域容灾及供应商迁移能力 |

**开放条件：** 私聊一旦开放，其举报、屏蔽、反骚扰与审核同步完成；交易和处罚的基础站内通知属于 P0。高级扩容可后置，首发容量验证和故障恢复不能后置。PK、KTV、AI 字幕、复杂算法推荐等暂不纳入首期基线；音乐等内容授权另评估。

## 3. 云服务、自有资产与服务器路线

| 范围 | 当前情况 | 商业版方向 |
| --- | --- | --- |
| 实时音视频、房间/麦位/房间消息 | 已接入腾讯 RTC / RoomEngine / IM 相关 SDK，耦合较深 | 首期继续使用；统一业务 ID、封装供应商接口，保留迁移空间。更换供应商需要适配与迁移，不是直接替换密钥 |
| 用户、业务订单、会员、举报和运营数据 | 自有基础后台；资金/治理域尚未完整实现 | 自有后台掌握权威记录，采用托管事务数据库，不把支付账本交给客户端或礼物特效 |
| 存储、审核、Push、备份与安全 | 不能由“已使用腾讯 RTC”推断已经开通 | 分别采购和接入；对象存储/CDN、审核、云数据库、异地备份等均需独立预算 |
| 业务服务器 | 当前单机 API、SQLite、本地头像；未做生产容量压测 | 先迁移数据库/对象存储与共享状态，再按可用性目标建设负载均衡与多实例，按压测和峰值增长扩容 |

音视频媒体主要走腾讯实时网络，业务 API、支付回调、审核与数据库仍有各自瓶颈。不能以现有机器规格或 HTTP 并发上限承诺在线人数。原生鸿蒙已有 TRTC 底层支持，但当前 iOS UI 不能直接复用，八麦、后台音频、房管互通与支付需先验证。[腾讯组件平台说明](https://cloud.tencent.com/document/product/647/105438)、[HarmonyOS 接入](https://cloud.tencent.com/document/product/647/130532)。

## 4. 建设周期与一次性预算

**规划场景：三端 + 业务后台 + Web 管理台 + 首发付费/治理闭环，8–10 人等效团队，4–6 个月，建设预算约 100–270 万元。** 包括语聊和基础视频直播；复杂 PK/KTV、重型推荐、公会分成平台等另立项。周期是排期假设，资质、商户开通、商店审核与鸿蒙验证可能影响上线日期。

| 建设项目 | 预算 | 估算依据 |
| --- | ---: | --- |
| 产品/设计、三端、后端/管理台、测试与运维研发人工 | 80–210 万 | 8–10 人 × 4–6 月 × 2.5–3.5 万/人月；综合人月成本为本方案假设，不是市场报价 |
| 外部安全测试、合规咨询与渠道接入等 | 5–15 万 | 预算占位，按实际业务资质、合同与专业机构报价确认 |
| 建设期云资源、SDK、测试设备/账号等 | 3–8 万 | 仅开发到上线前期间，避免与上线后的月度费用重复计算 |
| 预备费 | 约 9–35 万 | 以上三项之和的 10%–15% |
| **建设合计** | **约 100–270 万** | 原始计算约 97–268 万，取整用于资金计划；不是固定交付报价 |

建议排期：第 1 月完成范围、合规梳理、鸿蒙互通验证与商业底座设计；第 2–4 月并行建设三端、支付/治理和管理台；第 5–6 月完成跨端联调、支付对账、安全/容量/恢复验证、灰度上线。团队覆盖产品/设计、三端开发、后端/后台、测试、运维与安全协作。

## 5. 上线后的月度费用

### 5.1 云资源与通信成本示例

这是**语聊主导场景**：每天参与语聊的用户 1,000 / 5,000 / 10,000 人，每人每天 30 分钟，每月 30 天；按房间时长加权的平均在线人数为 10 人，假设每个房间一条混合音频连续审核。产品总 DAU 若包含不进房用户，需另乘语聊参与率。视频、逐轨审核等另算。

计算参考：多人连麦套餐 5,874 元/月，含 38 万音频等价分钟及对应 IM；超量纯语音 0.007 元/用户分钟；音频审核按 0.033 元/审核分钟。套餐资源只抵扣一次，已含 IM 不重复计基础费。上述为 2026-10-16 核对的公开参考价，实际套餐授权、折扣、计费项和限额需在采购时复核。[套餐](https://cloud.tencent.com.cn/document/product/647/105439)、[语音时长](https://cloud.tencent.com/document/product/647/44248)、[音频审核](https://cloud.tencent.com/document/product/1124/135178)。

| 每日语聊用户 | 月用户分钟 | 套餐 + 语音超量 | 假设混流音频审核 | 其他基础云服务预算 | **月云预算合计** |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 90 万 | 0.95 万 | 0.30 万 | 0.5–1.3 万 | **约 1.8–2.6 万** |
| 5,000 | 450 万 | 3.47 万 | 1.49 万 | 1.1–3.0 万 | **约 6.1–8.0 万** |
| 10,000 | 900 万 | 6.62 万 | 2.97 万 | 2.0–6.0 万 | **约 11.6–15.6 万** |

其他云预算包含业务服务器、托管数据库/缓存、对象存储/CDN、备份、监控日志、安全及增量短信/推送/图片文字审核等，为规划占位而非供应商报价。表内保留现有计费模型，**未包含视频、额外录制/转码/混流任务及其机器人订阅费、超出套餐限额的升档费用**。多人连麦参考套餐有 50 个未解散房间等限额，高用量行不代表该套餐可直接承载对应峰值。[计费说明](https://cloud.tencent.com/document/product/647/44248)

**敏感项：** 停留时长翻倍，语音用量近似翻倍；平均每房从 10 人降为 5 人，同等用户时长下假设混流审核费用翻倍。混流审核是否满足治理和发言人归因必须验证；若需逐轨全量审核，应提高预算。该审核量假设不代表完整的治理方案。

### 5.2 团队与经营支出

| 支出 | 月度预算或计算口径 |
| --- | --- |
| 持续研发、测试、产品和运维 | 4–6 人 × 2.5–3.5 万综合月成本 = **10–21 万/月** |
| 基础运营、客服、审核协作 | 暂设 **3–8 万/月**；按服务时段、人工量和风险重算，不能据此承诺全天多岗值守 |
| 团队小计 | **13–29 万/月**，可在自建和外包之间组合；与建设期人工按不同期间计算 |
| 渠道佣金、主播/公会分成、支付/结算、退款欺诈与税务 | 随收入或交易额变化，单列经营模型；如纳入上述外部费不得再次重复计提 |
| 获客投放、主播激励、内容版权、办公室及公司行政 | 单独设专项，未包含在建设和基础月运营预算内 |

在 1,000 语聊日活的上述纯语音模型下，**团队 + 云资源约 15–32 万/月**。如建设期之后预留 6 个月此规模的运行资金，建设 + 运行约 **190–462 万元**；这不是完整融资额，尚需叠加获客、内容供给、分成、视频与收入相关支出，并考虑实际收入回款。

iOS 数字商品支付按适用 App Store 规则和合同设计；渠道费率随计划、商品及发行渠道变化，不统一假定为 30%。大陆打赏、未成年人保护、备案和适用经营资质需在启动前由专业人员核对，不能以“云服务开通”替代。[Apple 审核规则](https://developer.apple.com/app-store/review/guidelines/)、[网信办直播打赏规定](https://www.cac.gov.cn/2026-04/13/c_1777815804150225.htm)。

## 6. 投资沟通建议关注的指标

用户活跃与留存、有效房间供给、进房成功率与稳定性、付费转化、每付费用户收入、退款/投诉/举报率、每语聊小时云成本、扣除渠道/分成/用量后的贡献利润、获客回收期。

**本文件用途：** 比较投入规模与建设顺序。预算为基于上述范围和假设的方案估算，已利用现有 iOS/后台基础进行规划；不能按代码量直接推导完成百分比。正式预算应由确认后的产品范围、人力计划、合规结论、云采购报价和峰值压测结果共同锁定。
