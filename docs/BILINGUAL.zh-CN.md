# KikiTalk 中英双语维护说明

本文面向工程维护和功能范围核对，记录本轮双语实现的边界与后续更新方式。当前词表包含 **1061 个基础 key，以及 7 个英文单数形式**；这些数字是本轮资源快照，不是测试通过数量。最终完整测试、英语系统原生界面验收和 TestFlight 交付结果由构建 50 的发布记录另行记录。

## 语言选择与会话

应用内入口为「设置 > 语言」，对应 `KikiAppLanguage` 的三种选择：

| 枚举值 | 显示选项 | 行为 |
| --- | --- | --- |
| `system` | 跟随系统 / Follow System | 按系统首选语言列表解析，默认使用此项 |
| `simplifiedChinese` | 简体中文 | 使用 `zh-Hans` |
| `english` | English | 使用 `en` |

跟随系统时，解析首选语言列表中的英文与中文；所有中文变体，包括繁体中文及不同中文地区，均使用当前简体中文资源。列表中没有受支持语言时回退为英文。

`KikiLanguageSettings.shared.selection` 将选择保存到 `UserDefaults` 的 `kikitalk.appLanguage`。语言设置独立于账号、协议同意记录和当前房间。SwiftUI 通过可观察设置及 `locale` 更新显示，不使用 `.id(language)` 重建根视图，因此切换语言不应销毁登录、房间连接、麦位或私信草稿等会话状态。

APNs 语言按**每个安装实例**登记，不是账号的全局语言。应用内选择变化后，需要按现有设备登记 revision 流程更新该安装的解析语言；同一账号在不同语言设备上可收到不同语言的系统通知。通知开关等既有账号偏好的范围不因此变化。

## 词表与生成资源

维护源位于：

- `localization/catalog/*.json`：按功能拆分的词表片段，包括客户端、服务端固定系统文案和关系说明。
- `localization/overrides.json`：对重复 key 的统一英文、需要区分中英文的语义 key，以及明确配置的英文单数形式。
- `localization/native_info.json`：应用显示名和系统权限用途说明等原生资源。
- `tools/build_kiki_localizations.py`：合并、校验和生成入口。

普通条目采用「中文源 key → 英文」形式，中文显示默认保留 key 本身：

```json
{
  "设置": "Settings"
}
```

需要独立中文值或单数时使用对象；支持 `zh-Hans`、`en` 和可选 `en.one`：

```json
{
  "%@ 个房间": {
    "zh-Hans": "%@ 个房间",
    "en": "%@ rooms",
    "en.one": "%@ room"
  }
}
```

同一 key 在不同片段中的翻译不一致时，必须在 `overrides.json` 明确统一，不能依赖文件排序覆盖。生成文件位于 `ios/KikiTalk/Resources/{zh-Hans,en}.lproj/`，包含 `Localizable.strings`、`InfoPlist.strings` 和 `KikiLaunchScreen.strings`；不要直接修改生成结果。

在仓库根目录生成或核对：

```sh
python3 tools/build_kiki_localizations.py
python3 tools/build_kiki_localizations.py --check
```

`--check` 核对片段冲突、源码显式调用的缺失 key、格式化占位符契约和生成资源是否过期。它不替代 Swift 编译、行为测试、截图检查或英语系统原生界面验收。

## 显示 API 与占位符

固定界面文案使用 `KikiL10n.text`，带动态参数的系统句子使用 `KikiL10n.format`，避免先插值再查词表：

```swift
Text(KikiL10n.text("设置"))
Text(KikiL10n.format("%@ 个房间", String(roomCount)))
Text(KikiL10n.format("查看%@的个人主页", person.name))
```

`format` 底层使用 `String(format:locale:arguments:)`。**`%@` 必须传入 `String` 等匹配的对象参数，数字先转为 `String`；不要把整数直接传给 `%@`。** 如采用其他格式类型，实参与中英模板必须保持相同的位置、数量和类型。英文可用 `%1$@`、`%2$@` 调整语序，不能遗漏、增加或改变原参数类型。

英文单数形式只为已明确配置 `en.one` 的计数 key 生效：第一个参数为数量且值为 `1` 时选择单数，其余使用通常英文模板。不要为昵称、消息或其他非计数参数推断单复数；增加新计数句时同时检查 `0`、`1` 和多个数量的表达。

`KikiL10n.placeName(rawName)` 仅用于内置中国地区目录的显示。英文使用规范省市名称及无声调拼音，并按地区类型补充 `City`、`District`、`County` 等后缀；中文保留原值。列表、导航标题和已选出生地名称可调用此方法，**不得将返回值用作地区 ID，也不得写回出生资料或发送给服务端替代原始名称**。出生地默认中国、历法与真太阳时的既有计算规则保持不变。

## 已覆盖范围与内容边界

本轮覆盖登录及首次昵称引导、房间发现与创建、房间工具和麦位、关系图与说明、个人资料和设置、社交与私聊、错误提示、通知、权限用途说明，以及英文应用显示名 `kikitalk`。中文原生显示名保留 `Kiki`。

固定系统通知不能一概视为用户内容：关注、互关、开播和邀请等按稳定 `kind`、原始 actor 及系统语义生成英文模板，昵称作为参数原样嵌入。消息列表预览和前台通知应使用对应显示属性，而不是直接展示嵌入中文系统句子的原始通知 body。安全通知的固定文案和管理动作前缀可以本地化，未知或自由编辑的运营说明保留原文；原始通知记录不改写。

以下内容保留原值：

- 用户昵称、简介、私信正文、房间名称、房间公告和举报补充说明等用户内容。
- 账号和房间 ID、地区编码、请求字段、传输协议枚举及状态码。
- 真实出生资料、历法输入、协议日期格式和服务端计算输入；四柱本身也不改写为另一套数据。

本地化只改变显示。出生资料和八字仍仅本人可见，房间公开展示范围不扩大；MBTI 与生日生成的公开星座标签按既有规则展示。编辑个人资料的入口和房间内权限规则也保持原有边界。

## 布局与原生系统界面

房间主体维持固定房间布局，不通过增加整页滚动来容纳英文。关系模式选择器、图例与星座短名使用适合可用空间的英文，完整含义保留在说明与可访问性文本中。

普通字号按钮允许按英文长度自然伸缩或换行；辅助功能字号下，资料操作及关系列表可改为纵向布局，关系切换可采用菜单。设置菜单在辅助功能字号下将装饰图标与箭头置于上方，让标题使用完整行宽。收件箱和通知预览允许合理多行，不用针对中文的固定文字宽度或过度缩字挤入英文。验收应包括小屏、明暗主题、大字、长昵称及不同数字数量。

应用内语言选择只控制应用自有显示及注入的区域设置。Apple 原生登录按钮、Apple 授权界面、系统权限弹窗、照片选择器及其他系统界面仍遵循 iOS 对应用或系统语言的选择，不能承诺随应用内菜单立即切换。`InfoPlist.strings` 和启动资源提供中英文，但主屏幕应用名等原生资源也由 iOS 选择。因此英语系统环境需要单独验收，不能只靠中文系统内切换 English 的截图代替。

## 英文协议与同意记录

英文协议覆盖隐私政策、用户协议、第三方 SDK 清单和系统权限说明四份文档，共 **78 段正文**。英文版本是当前中文规范文本的完整显示译文，不是重新签署一套独立条款。

本轮保持 `2026-11-13-r18` 规范文本及其 canonical `documentHash` 不变。英文资源通过 `sourceDocumentHash` 绑定同一规范文本，并使用独立 `renderingHash` 校验英文展示内容；客户端和服务端需要核验版本、文档结构、完整性及 hash 绑定。不能用错误版本、部分英文或不匹配缓存替代当前完整协议。

单纯切换语言不重置既有同意、不要求重新签署。只有既有协议更新、撤回同意等规则触发时，才按原流程重新确认。英文资源暂不可获取或验证时，应显示明确状态并允许联网重试，不能绕过当前协议确认要求。

## 服务端兼容与发布边界

设备通知语言使用附加表 `push_device_languages` 保存，避免改动旧版服务依赖的主设备表字段布局。旧设备或没有语言记录的设备继续按既有中文默认值处理；新增登记支持每安装语言和 revision 约束，并保留旧请求重试的兼容处理。附加表可以在代码回滚时保留，不能为回滚删除通知登记、账号凭据或业务数据。

本轮服务端发布范围限定为现有 Kiki 账户、官网及独立语聊服务中相关代码和协议资源。同机 companion 服务不属于发布目标，不应因本轮发布被替换、重启或修改配置与数据。部署前仍需检查线上差异、保留回滚版本，部署后核验相应服务与公网健康；客户端代码本身不能当作服务端发布内容。

本文不代表构建已上传、TestFlight 已可安装或服务已成功上线。实际部署范围、回滚位置、完整测试与英语系统原生界面结果，以及最终版本和上传状态，以本轮发布记录为准。
