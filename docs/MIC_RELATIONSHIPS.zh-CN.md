# 圆形麦位与私密关系计算

日期：2026-11-13。开发分支：`codex/kiki-development`。用户 App 本轮版本：**1.0.301（45）**。

本文记录当前实现、验证和实际发布。账号服务、语聊服务及配套官网协议已发布；客户端界面需要安装新版 App 才能生效。

## 界面与资料

房间按服务端已经确认的占麦成员显示 1–8 个头像，均匀分布在圆周。头像以稳定 `userID` 标识，按真实 `seatIndex` 排序，保留锁麦造成的编号间隙。短暂断线继续显示灰态头像；服务器释放麦位后才离场、补位。头像及连线端点由同一份约 500 毫秒动画坐标驱动，连续变化从当前显示位置接续。系统“减弱动态效果”开启时使用即时布局。

用户可本地切换八字、MBTI、星座，选择不会改变其他用户的视图或语聊状态。圆环中央不显示人数。头像单击仍打开个人主页；通过“查看关系”选择一对后高亮对应连线。聊天、听众、申请／审批／邀请上麦、禁麦、下麦、最小化和原有安全操作继续使用现有业务链路。

“关系资料”编辑器由个人资料及房间入口共用。MBTI、星座可以公开并参与相应关系展示；出生日期、出生时刻、出生地、时区、真太阳时和四柱仅本人可见。出生信息允许公历／农历录入，农历明确区分闰月。公农历转换与八字预览均请求服务端，iOS 不实现八字或真太阳时算法。

八字参与开关默认关闭。允许部分保存；未知出生时刻不补默认中午，不生成唯一四柱。只有双方资料完整且都开启参与，房间才返回八字计算结果。关闭参与保留本人已保存资料、停止对外返回该类结果；清空出生资料、撤回同意及删除账号分别按实际操作清理在线私密资料。账号删除使用数据库外键级联，撤回同意显式删除关系资料表记录。

## 接口与隐私边界

以下公开 HTTPS API 均使用账号服务 `kiki.group` 的账号 Bearer；不向语聊域名发送该 token。

| 接口 | 作用与范围 |
| --- | --- |
| `GET /v1/me/relationship-profile` | 读取本人私密资料、排盘结果及资料版本 |
| `PATCH /v1/me/relationship-profile` | 部分更新本人资料和参与设置；显式 `null` 用于清空可选字段 |
| `POST /v1/me/relationship-profile/preview` | 服务端转换历法并计算本人预览，不持久化 |
| `GET /v1/relationship-places?parent=地区编号` | 查询出生地目录；省略 `parent` 返回根目录 |
| `GET /v1/voice/rooms/{roomID}/relations` | 核验调用者当前房间身份，返回当前占麦成员的关系结果，最多 28 对 |

私密输入字段为 `birthCalendar`、`birthDate`、`birthLeapMonth`、`birthTime`、`birthPlaceCode`、可选 `birthFold`；设置字段为 `mbtiType`、`zodiacSign`、`baziEnabled`、`mbtiEnabled`、`zodiacEnabled`。出生地名称、坐标及 IANA 时区由服务端按目录编号解析，客户端不能提交任意经纬度代替目录数据。历史夏令时空档拒绝保存；回拨重复时刻需通过 `birthFold=0/1` 明确第一次／第二次。

本人响应含 `chart.status`（`ready` 或 `incomplete`）、可选四柱／真太阳时，以及两套历法对应日期。完整出生日期存在时，星座从换算后的原始公历生日按简化日期规则生成，不使用真太阳时跨日后的日期；未填写生日时可以单独选择星座。

公开个人主页仅通过白名单增加 `mbtiType`、`zodiacSign`。出生资料、四柱不进入通用用户序列化、账号→语聊身份桥接、`roomState.members` 或 LiveKit 属性／数据消息。关闭某类公开参与后，对应公开标签也不返回。

房间响应只包含 `roomID`、`roomRevision`、不透明结果 `revision`、`ruleVersion`、公开标签 `profiles` 和 `pairs`。配对内只有双方 `aID/bID` 及各模式的 `code/label/description`、允许展示的汇总指数。不得增加出生信息、四柱、日主、“某人日支”或“辰酉六合”等逐柱证据。结果本身会表达一定关系特征，因此不承诺从结果无法推断任何信息。

语聊服务仅提供签名内部路由：

- `POST /internal/v1/account/relationship-members`：账号服务提交调用者及房间编号，语聊服务按有效会话、同意状态、权威麦位和双向屏蔽返回成员 ID 与房间版本。
- `POST /internal/v1/account/relationship-refresh`：只有账号 ID 的失效提示，递增其所在活动房间版本；不传出生资料或计算结果。

账号服务再核对社交屏蔽、有效同意和调用者会话。计算完成后复核资料版本；计算中发生资料更新、关闭参与、撤回或删除时拒绝发布旧结果。接口成功及错误响应均 `no-store`，验证错误不回显请求正文，普通异常日志仅记录异常类型。关系结果不做持久缓存；私密资料只在本人编辑器生命周期内持有，不放入全局 AppStore 或公共模型。

## 固定算法与数据

- 关系规则版本：`kiki-relations-1.0.0`。
- 排盘版本：`true-solar-1.0.0-lunar-python-1.4.9`；服务端依赖固定为 `lunar-python==1.4.9`（MIT）。
- 真太阳时参考只读的“赛博算命”项目，使用出生经度和 NOAA/Meeus 均时差。年柱按真实立春、月柱按真实十二节；日／时柱按出生地真太阳钟面，sect 2 零点换日。节气表用固定 UTC+8 表示真实时刻，不将历史夏令时重复扣除。
- 原始公历出生年份范围 1900–2100；校正后真太阳日期允许跨到相邻年份。日期／地点／时刻不完整时输出待完善，不任选候选四柱参与固定关系。
- 八字仅比较跨盘地支六合、六冲；四柱位置权重依次为 `1、2、4、1`，单项取两侧较小权重，同一无序地支关系只计最大权重。合、冲分别按 `floor((100 × 权重和 + 4) / 8)` 汇总，不相互抵消。这是本应用固定演示规则，不是传统统一评分或成功率。
- MBTI 使用固定 OnType 社区黄金／白银／师生配对表，另含同类型、其他组合；不将名称当作高低保证。星座按十二标签最短间隔分类为同星座、相邻、六分、刑、拱、梅花、对宫，不宣称精确行星相位。
- 八字 `NONE` 表示本规则未命中直接合冲；`UNAVAILABLE` 统一表示暂无法展示，不向他人区分未填写、未参与或私密资料缺失。

离线出生地目录覆盖大陆、香港、澳门、台湾，共 **3,633** 条、全部有代表坐标。大陆层级来自 modood 项目固定快照（WTFPL）；坐标和港澳台层级来自 GeoNames（CC BY 4.0），补充坐标包含 Wikidata（CC0）。它们是地区代表点，不是医院或门牌精确位置，小数位数不代表测绘精度。源版本、链接、快照哈希和补充说明保留于 `backend/app/relationship_places_sources.txt`；历法依赖许可见 `relationship_lunar_license.txt`。

## 客户端刷新与失效

舞台使用已有 RTC 接受的房间快照，不另建成员权威。请求范围包含房间、本人账号、隐私版本、房间 revision、占麦成员和前台／最小化状态。范围变化即清空关系结果，旧请求不能覆盖新范围；低于已接受房间 revision 的服务器结果被拒绝。资料保存会发本机刷新通知，切房、切账号、离开舞台或请求失败也会清除旧结果。

舞台活跃时每轮请求结束后等待 **5 秒**再补拉，作为丢失刷新提示时的补偿。网络延迟、断线和服务器状态传播仍会影响外部用户何时看到撤回，不能承诺所有客户端即时或严格 5 秒内更新。重新进入舞台会重新请求；动画不会成为保留已失效关系证据的理由。
