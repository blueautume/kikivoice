# 圆形麦位与私密关系计算

更新日期：2026-11-13。开发分支：`codex/kiki-development`。本轮应用目标版本：**1.1.2（49）**。

本文记录最终界面设计和代码行为。本轮测试、签名包和 TestFlight 记录见 [RELEASE_1.1.2_BUILD_49.zh-CN.md](RELEASE_1.1.2_BUILD_49.zh-CN.md)；此前发布记录见 [RELEASE_1.1.2.zh-CN.md](RELEASE_1.1.2.zh-CN.md)。后续默认保持营销版本，仅递增构建号，除非用户另行指定。

## 房间展示

房间按服务端确认的占麦成员显示 1–8 个头像，不预留八个空头像：

- 单人时头像位于圆环中心；第二人加入后，所有在麦头像沿圆环均匀分布。
- 圆环始终提供位置参照，中央不显示人数。
- 头像以稳定 `userID` 标识，按权威 `seatIndex` 排序；麦位编号沿用语聊服务状态，保留锁麦造成的间隙。
- 上下麦重排约 500 毫秒。头像位置和曲线端点使用同一份动画坐标，连续变化从当前显示位置接续；系统开启“减弱动态效果”时即时布局。
- 短暂断线按服务端重连宽限保留灰态头像，服务端释放麦位后才离场。资料失效时立即清除旧关系，不为退场动画保留失效结果。

右下角紧凑选择器按“八字”“星座”“MBTI”排列，切换只改变本机展示。所有可展示配对使用较粗、轻微弯曲的线条同时呈现，无需选择单对或执行高亮操作。颜色与实线、虚线、点线共同区分关系；八字“合冲并见”以相合、相冲两条曲线分别表达，分布在头像连弦两侧，中段约留 20pt 间距。八字仅展示相合、相冲、合冲并见三种关系；MBTI 仅展示黄金、白银、师生及同类型。内部 `NONE` 和 `OTHER` 计算代码保留以兼容接口，但不绘制连线、不进入图例或当前配对卡片，也不改归到其他已有类别。`UNAVAILABLE` 不绘制连线，避免将未知资料显示为一种关系。

圆环下沿固定放置该模式所有可展示类别的图例，右侧为紧凑切换器；图例不因当前房间尚未出现某种关系而隐藏。“关系说明”使用“默契合拍”“欢喜冤家”“互补来电”等直观的娱乐配对标题与短说明，并显示谁与谁对应哪类配对；原类别作为小字保留，便于对照图例。该页仅用于查看，不筛选或高亮曲线。星座图例包括同星座、相邻、六分、刑、拱、梅花、对宫；MBTI 图例包括黄金、白银、师生、同类型。

八字模式的昵称下方不保留 MBTI／星座标签占位，底衬随内容贴合；切换到 MBTI／星座时，公开标签平滑出现，头像及关系端点的位置保持稳定。

顶部、圆环、图例、听众和操作按钮按完整静息窗口高度固定排布，按可用空间压缩圆环及间距；房间中央没有纵向滚动区域或渐隐裁切。只有聊天历史保持自身滚动。输入框和发送按钮由独立键盘区域定位，键盘升降只改变输入区位置，主画布的尺寸和窗口坐标保持不变，系统键盘可以覆盖下层内容。底部按钮保留完整触控区域，房间背景连续铺满窗口。

头像点击仍查看个人主页。房间及房内个人主页没有关系资料编辑入口；用户须回到“我”修改。聊天、听众、申请／审批／邀请上麦、禁麦、下麦、最小化和原有安全操作继续沿用语聊业务链路。

## “我”中的资料入口

“我的社区”上方提供两个独立入口：

| 入口 | 可编辑内容 | 只读展示 |
| --- | --- | --- |
| 八字 | 出生地、公历／农历生日、农历闰月、当地钟表时刻 | 服务端生成的星座、本人四柱和真太阳时 |
| MBTI | 十六种类型，可暂留未知 | 当前选择 |

头像右下角的编辑入口只修改头像和昵称，不再混入简介或关系资料；保存时保留既有简介。星座没有单独入口或手选项，由生日自动生成；没有生日时显示待完善，不使用旧手选值兜底。

出生地默认使用中国地区目录，包含大陆和港澳台，不申请定位权限、不自动使用当前位置。服务端按所选地区解析坐标和时区，客户端不展示时区选择或 IANA 时区名称，也不让用户选择历史夏令时或重复钟点。用户只填写出生地记录的钟表日期与时刻。历史时制由服务端处理，重复钟点固定采用第一次；不存在的当地钟表时刻拒绝保存并提示核对。

公农历转换、星座、八字和真太阳时均由服务端计算。未知出生时刻可留空，不补默认中午，不产生唯一四柱。生日已完整时可先生成星座，出生日期／地点／时刻不完整时八字显示待完善。大字体下 MBTI 和四柱预览改用两列，保持小屏幕可读。

资料页仅保留简短事实说明：出生资料和八字仅本人可见，房间只显示计算结果；MBTI 和星座公开展示。没有参与、公开或共享开关，也不重复弹出确认。

## 协议与隐私边界

本轮适用协议版本为 **`2026-11-13-r18`**。使用相关功能须接受当前完整隐私政策及用户协议；协议入口的可见摘要说明已填写出生资料用于服务端八字关系计算、MBTI 与星座作为公开标签。资料可以未知或留空，但已接受当前协议后不存在独立的逐类参与开关。未接受当前协议的账号不得读取私密资料接口、产生有效对外标签或参与房间关系结果。

出生日期、历法／闰月、出生时刻、出生地及坐标、时区、真太阳时和四柱只通过本人私密接口返回；iOS 仅在编辑器生命周期持有，不存入全局 AppStore 或公共人物模型。公开个人主页仅增加白名单字段 `mbtiType`、`zodiacSign`。私密出生资料和四柱不进入通用用户序列化、账号到语聊身份桥接、`roomState.members`、LiveKit 属性或数据消息，也不发送给 AI 服务。

房间接口只返回房间版本、公开标签和两两关系汇总。配对结果允许 `aID/bID`、各模式的 `code/label/description` 及允许展示的汇总指数，不返回出生资料、四柱、日主或逐柱合冲证据。结果本身会表达一定关系特征，不承诺从结果无法推断任何信息。

撤回同意会停止相关功能并清理在线私密关系资料；删除账号通过外键级联清理。数据清理、备份范围和授权撤回规则以当前协议及对应账号逻辑为准。

## 接口与独立保存

以下公开 HTTPS API 使用账号服务 `kiki.group` 的账号 Bearer，不向语聊域名发送该 token：

| 接口 | 作用与范围 |
| --- | --- |
| `GET /v1/me/relationship-profile` | 读取本人私密资料、计算结果、历法对应日期及版本 |
| `PATCH /v1/me/relationship-profile` | 部分更新本人可编辑资料，显式 `null` 清空可选字段 |
| `POST /v1/me/relationship-profile/preview` | 服务端转换历法、派生星座并计算本人预览，不持久化 |
| `GET /v1/relationship-places?parent=地区编号` | 查询出生地目录，省略 `parent` 返回中国地区根目录 |
| `GET /v1/voice/rooms/{roomID}/relations` | 核验当前房间身份，返回权威占麦成员的结果，最多 28 对 |

两个编辑页均先读取服务端当前资料，但保存使用独立 PATCH：

- MBTI 页只发送 `mbtiType`。
- 八字页只发送 `birthCalendar`、`birthDate`、`birthLeapMonth`、`birthTime`、`birthPlaceCode`。
- 预览可发送上述完整可编辑草稿；客户端不发送计算好的四柱、坐标或时区。

服务端以 `exclude_unset` 合并字段，并在事务内完成读取、合并和保存；省略的字段保留，避免 MBTI 保存覆盖出生资料，或八字保存覆盖 MBTI。旧客户端的 `zodiacSign`、`birthFold`、`baziEnabled`、`mbtiEnabled`、`zodiacEnabled` 为兼容仍可接收，但不作为用户选择生效；新客户端不编码这些字段。本人响应中的 enabled 字段维持兼容并反映协议下的有效参与，`birthFold` 返回 `null`，不表示存在可编辑选项。

星座始终从换算后的原始公历生日派生，使用简化日期规则，不使用真太阳时跨日后的日期。无有效生日时返回 `null`，不会恢复旧的手选星座。时区由服务端可信地区目录决定，历史重复钟点统一按第一次解析，不沿用旧 `birthFold=1`。

语聊服务仅提供签名内部路由：

- `POST /internal/v1/account/relationship-members`：按调用者有效会话、当前协议、权威麦位及双向屏蔽，返回成员 ID 与房间版本。
- `POST /internal/v1/account/relationship-refresh`：接收只有账号 ID 的失效提示，递增其所在活动房间版本，不接收出生资料或计算结果。

账号服务还核对社交屏蔽、当前协议和调用者会话，计算后再次复核资料版本及账号资格。计算中发生资料更新、撤回或删除时拒绝发布旧结果。成功和错误响应均为 `no-store`，验证错误不回显请求正文，普通异常日志仅记录异常类型。关系结果不做持久缓存。

## 固定算法与数据

- 关系规则版本：`kiki-relations-1.1.0`。
- 排盘版本：`true-solar-1.1.0-lunar-python-1.4.9`；服务端固定依赖 `lunar-python==1.4.9`（MIT）。
- 真太阳时参考只读的“赛博算命”项目，使用出生经度和 NOAA/Meeus 均时差。年柱按实际立春、月柱按实际十二节；日／时柱按出生地真太阳钟面，sect 2 零点换日。节气表用固定 UTC+8 表示真实时刻，不重复扣除历史夏令时。参考项目不在本轮修改范围。
- 原始公历出生年份范围 1900–2100；真太阳时校正允许跨至相邻年份。资料不完整时不任选候选四柱参与计算。
- 八字只比较跨盘地支六合、六冲；四柱权重依次为 `1、2、4、1`，单项取两侧较小权重，同一无序地支关系只计最大权重。合、冲分别按 `floor((100 × 权重和 + 4) / 8)` 汇总，不相互抵消。输出相合、相冲、合冲并见或未命中直接合冲。这是本应用固定演示规则，不是传统统一评分或关系成功率。
- MBTI 使用固定 OnType 社区黄金／白银／师生配对表，另含同类型、其他组合，名称不表示好坏排名。
- 星座按十二标签最短间隔分类为同星座、相邻、六分、刑、拱、梅花、对宫，属于标签间隔的简化结构，不是精确行星相位或完整星盘合盘。
- 八字 `NONE` 表示本规则未命中直接合冲，不表示不适合；`UNAVAILABLE` 统一表示暂无法展示，不向他人区分某人的具体缺失字段或协议状态。

离线出生地目录覆盖大陆、香港、澳门、台湾，共 **3,633** 条，均有代表坐标。大陆层级来自 modood 固定快照（WTFPL）；坐标和港澳台层级来自 GeoNames（CC BY 4.0），补充坐标来自 Wikidata（CC0）。坐标为地区代表点，不是医院或门牌精确位置；小数位数不代表测绘精度。来源、版本与哈希见 `backend/app/relationship_places_sources.txt`，历法依赖许可见 `backend/app/relationship_lunar_license.txt`。

## 刷新、验证与发布边界

舞台使用已有 RTC 接受的房间快照，不另建成员权威。请求范围包含房间、本人账号、隐私版本、房间 revision、占麦成员和前台／最小化状态。范围变化即清空结果，旧请求不能覆盖新范围；低于已接受房间 revision 的服务器结果被拒绝。资料保存发出本机刷新通知；切房、切账号、离开舞台或请求失败也会清除旧结果。

舞台活跃时每轮请求结束后等待 **5 秒**再补拉，补偿丢失的刷新提示。网络、断线和服务器状态传播会影响其他用户何时看到失效，不能承诺即时或严格 5 秒内更新。重新进入舞台重新请求。

本轮验收应覆盖：单人居中到多人圆环的连续动画、所有关系曲线和完整图例、三模式切换、房内仅查看、两个资料页的独立保存、自动星座／历史时制、r18 门禁、私密字段白名单、失效刷新，以及小屏幕／深浅色／大字体。这里列出验收范围，不替代实际测试结果。

服务端使用 `backend/deploy/deploy_kiki_only.py` 做 Kiki 差异检查、回滚保留及健康核验。发布前分别检查：

```sh
python3 backend/deploy/deploy_kiki_only.py voice --check
python3 backend/deploy/deploy_kiki_only.py account --check
```

本轮没有新增依赖，不需要 wheel 安装步骤。发布仅涉及 Kiki 对应账号、语聊和协议资源，保留凭据、业务数据与现有配置，不修改同机新增的陪玩管理台服务。客户端界面须安装新的 App 才能生效，推送 TestFlight 与服务端部署是分别核验的发布步骤。
