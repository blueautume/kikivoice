# 商业版治理、财务与安全运行规范

> 规划文档，未实施；核对日期：2026-10-16。适用于中国大陆首发并开放充值、礼物或会员。文中时限均为拟定目标，未经压测、演练及值班配置不能宣称达标。

## 1. 上线边界与责任

🔴 P0：实名与账号安全、实时审核、举报处罚申诉、客服、订单账务退款、未成年保护、管理台审计、监控及恢复；🟠 P1：运营配置、质检和报表；🟡 P2：自动策略与精细运营。商业首发必须有人负责审核、客服、财务及值班，购买云服务不能转移平台责任。

当前设备绑定 ID 登录、24 小时 UserSig 和房主管理仅构成功能基础，尚无本规范的商业治理闭环。经营资质需按主体所在地、公开音频/视频、表演内容、收费与主播经纪逐项确认，不能仅凭“语聊”判断。APP 备案应纳入发布门禁；[工信部通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)不能替代其他适用许可。

## 2. 举报案件与全域处罚

案件字段至少包含：`case_id`、举报人与被举报业务 UID、SDK 用户 ID、对象类型/ID、房间/消息/订单 ID、事件时间和时区、类别/严重度、描述、证据引用与 hash、快照、规则/模型版本、负责人、受理/处置时限、决定/理由、通知与申诉记录、保全期限。禁止把 UserSig、证件原图和支付密钥写入案件正文。

状态机：`received → triaged → investigating → decided → enforcing → verified → closed`；不成立使用 `dismissed`，需复核使用 `reopened`。证据不足须记录理由；紧急先限流/断流可并行，但必须补记依据。每次状态变更追加事件，不能覆盖历史；举报回执不暴露举报人身份。

处罚对象区分平台账号、指定房间和具体内容；措施区分禁言、禁私聊、禁麦、禁开房、关房、账号封禁及营利限制。保存 `sanction_id/scope/reason/start/end/decision_version`，按法律和社区规则告知，并提供申诉。[APP 管理规定](https://www.cac.gov.cn/2022-06/14/c_1656821626455324.htm)要求便捷举报及受理、处置、反馈机制。

执行通过事务事件表投递，每个系统记录幂等键、尝试次数、云端请求 ID、业务错误码、验证结果：

| 执行面 | 必须动作与验证 |
|---|---|
| 业务 API | 撤销相关会话；登录、SDK 续签、发消息、上传、支付逐一校验范围 |
| IM | 禁言/限制发送、踢会话及失效历史凭证；验证旧 UserSig 登录、群聊与私聊均符合处罚 |
| 房间/RTC | 下麦、停止发布、移出或关房；验证另一台设备不再收到被禁音频且不能重新进入/发布 |
| Push/运营 | 停止不应投递的营销和召回；必要的处罚/申诉通知另行保留 |
| 收益 | 限制营利/冻结争议收益；退款与用户资产查阅保留受控通道 |

腾讯 [IM 失效登录接口](https://intl.cloud.tencent.com/zh/document/product/1047/34957)对历史凭证有效，但新签发凭证仍能登录；HTTP 200 也需检查业务错误码。该接口不能据此推定 TRTC 同步封禁。必须针对现用 TUILiveKit/RoomEngine/IM/TRTC 套餐验证管理 API、回调、进房与发布鉴权；任一环节未闭环不得宣称全域封禁，不能靠客户端隐藏按钮或反复踢人兜底。

执行失败进入重试/死信并告警，页面显示“部分执行失败”；严重违规无法阻断时暂停该房间或相关服务。解封复核者与原处罚者分离，确认无其他有效处罚后逐系统撤销并复测；退款、历史记录及过期权益不因解封自动回滚。

## 3. 审核与人工值班

昵称/头像/封面/公告、文字、图片先经审核状态控制发布；音视频采用受告知的实时检测链路。采集事件绑定房间、轨道、SDK UID、麦位及有效时间，保留上下麦和重连映射，不能把混流中的违规直接归给房主。云回调验签、校验时间窗并去重；审核任务失败重试，结果延迟和采集空洞单独告警。

开放时段覆盖人工巡查和升级值班，全天开放即需全天覆盖。高危案件优先，审核员可断流但不可改余额；抽检漏检/误判与申诉改判率。供应商失联时限制新开播和高风险发布，转人工或暂停，而非全部放行。录制用途、提示、访问权及保留方案上线前经法律确认；[直播管理规定及官方解释](https://www.cac.gov.cn/2016-11/04/c_1119847606.htm)包含即时阻断、内容管理及留存要求。

## 4. 付费、退款及未成年风控（P0）

订单与账本分离，金额用最小货币单位整数，币种与虚拟币单位分别记录。交易号唯一；服务端核验购买人与商品、环境、金额及签名后，原子写入复式流水和权益，禁止管理员直接改余额。超时订单主动查单；回调重复/乱序只能入账一次。礼物扣币、主播待结算与平台收入可追溯；付费币/赠币分账。退款追加冲正，不删除原交易；每日渠道订单、到账、退款、账本、银行结算对账，差异进入人工工单。

| 客户端 | 发布与交付门禁 |
|---|---|
| iOS | 大陆数字商品按 [Apple 3.1](https://developer.apple.com/app-store/review/guidelines/)规划 IAP；StoreKit 2、服务端验签、[Server Notifications V2](https://developer.apple.com/documentation/appstoreservernotifications/receiving-app-store-server-notifications)、补单、恢复会员与退款撤权一起验收 |
| Android | 各商店分别核对支付及SDK规则；渠道商品映射与订单隔离，不把微信/支付宝接入视为所有渠道已通过 |
| HarmonyOS | 使用对应原生 IAP 流程及服务端查单/发货确认；不复用 Android 安装包或购买 Token。[华为交付说明](https://developer.huawei.com/consumer/en/doc/harmonyos-references-V13/iap-confirm-purchase-for-order-V13)要求每个 Token 只交付一次 |

客服受理退款，财务复核，渠道执行并跟踪最终结果；Apple 渠道退款按其机制处理，不以本地标记退款成功代替。主播可提现时，首发另完成实名合同、税务、分成版本、冻结/可结算/已结算、退单追偿和持牌机构结算；未设计可提现业务时不应直接将普通虚拟币系统定性为银行或支付机构。

打赏提供首次限额设置、默认开启提醒、异常大额确认；保护消费统计隐私，禁止仅以打赏金额排名。2026 [打赏管理通知](https://www.cac.gov.cn/2026-04/13/c_1777815804150225.htm)采用分龄规则；产品首期可更严格地禁未成年打赏，并核验疑似借用成人账号。禁言与营利权限联动、监护人投诉及未成年退款必须覆盖。

## 5. 后台职责分离

所有管理账号 MFA、按职责最小授权、操作原因必填，离职立即撤权；临时提权有到期时间。

| 角色 | 可执行 | 禁止/需复核 |
|---|---|---|
| 客服 | 脱敏查单、回执、退款申请 | 不改余额、不看全量录音 |
| 审核 | 授权案件证据、紧急断流、处罚建议 | 永封/解封按规则复核；不结算 |
| 风控复核 | 重大处罚、申诉、规则发布 | 不复核本人决定 |
| 财务 | 对账、退款复核、收益审核 | 申请与批准分人；不改原流水 |
| 运营 | 活动、推荐、模板与人群申请 | 不查证件/私聊；批量Push需审批 |
| 运维 | 部署、扩容、备份恢复、密钥轮换 | 不默认具备业务明文读取权 |
| 审计 | 只读审计和授权导出 | 不修改业务、权限和审计记录 |

## 6. 注销、保全与分类留存

注销状态：`requested → verified → processing → completed/partial_failure`。撤销会话并停止新业务；编排业务库、IM资料、对象/CDN、索引缓存、Push Token和第三方删除，保存回执。保全只锁定相关数据，由授权人批准、定期复查和到期解除，不冻结整个账号全部数据。[个人信息保护法第47条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)区分删除与依法暂存，后者限制其他处理；[Apple 要求](https://developer.apple.com/support/offering-account-deletion-in-your-app/)支持应用内发起真正删除。

| 数据类别 | 保留规则与销毁 |
|---|---|
| 网络安全日志 | 按现行[网络安全法第23条](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)不少于6个月；脱敏、限权、防篡改 |
| 直播内容/音频 | 按适用直播/表演规则核定对象、采集形式及期限；不能把安全日志6个月直接套给全量录音；法律确认是上线门禁 |
| 举报证据/处罚/申诉 | 依案件时效和争议处理制定期限；保全优先，到期审批销毁 |
| 订单/税务/结算 | 财务法律确认各类法定期限；与普通聊天隔离，不因注销立即删除 |
| 聊天/头像/设备Token | 明示业务期限；替换、失效、注销触发删除，纠纷保全例外 |
| 备份/导出/分析数据 | 备份拟滚动35日、导出链接拟24小时失效；法律保全另存；恢复后重放删除清单，脱敏不能冒充匿名化 |

## 7. SLO、手册与首发验收

拟定目标：核心业务月可用性99.9%；处罚决定后95%可执行操作10秒内验证，超30秒告警；高危举报5分钟内人工接手。事故5分钟响应、10分钟升级、每30分钟更新状态；核心数据库恢复RTO≤60分钟、完整业务恢复RTO≤2小时，一般业务数据RPO≤15分钟，须由演练验证。资金数据另定持久性与恢复要求，通用RPO不是允许丢失已提交交易；恢复时结合渠道记录与独立内部账务/业务凭据核对充值、送礼、退款及人工调账后补偿复核，不宣称备份保证零丢失。

手册顺序：分级与指挥人→冻结发布/收费或隔离风险房→保全证据→回滚/切换→核对订单和数据→恢复放量→复盘。审核故障、云封禁失败、支付回调积压、账务不平、密钥泄露、数据库恢复分别建立演练；疑似泄露另启动适用法定报告流程。

首发签收用例：①旧UserSig与改造客户端绕过业务API仍不能发言/重入；②双端举报、证据归属、超时升级、误罚申诉解封；③同笔回调重放/乱序、断网补单、退款后撤权与收益追偿；④未成年借号及监护退款；⑤低权限管理员越权被拒并留痕；⑥注销部分失败重试、法律保全及备份恢复后删除重放；⑦审核服务失联和多可用区/备份恢复演练。未通过的P0用例阻止对应商业功能发布。
