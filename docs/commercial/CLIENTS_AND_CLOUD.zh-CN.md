# 多客户端协议与云服务边界

> **归档规划（2026-10-16；2026-10-22 标注）：** 本文保留当时的预算、腾讯方案与功能起点，不是当前架构、依赖或已交付功能清单。当前主线为 Apple 登录、自建 LiveKit、账号/社交及独立运维 App；已移除旧腾讯 iOS 组件、示例和实验客户端。当前入口见[项目接手指南](../PROJECT_HANDOVER.zh-CN.md)与[架构说明](../ARCHITECTURE.zh-CN.md)。本次仅整理文档，不重估预算或更新历史验收。


日期：2026-10-16。面向中国大陆、首发包含礼物/充值或会员的规划文档；以下协议与验收是建议，**不是已上线实现**。当前可确认 iOS 与自有 API、腾讯 Live/RoomEngine/TRTC 已接通；Android、原生鸿蒙、业务管理台、支付和完整私聊/Push 仍需建设。腾讯套餐、授权、额度和控制台开关无法从代码确认。

## 客户端职责矩阵

| 职责 | iOS | Android | 原生 HarmonyOS | Web 管理台 |
| --- | --- | --- | --- | --- |
| 技术与入口 | 延续 SwiftUI/UIKit | Kotlin/原生页面 | ArkTS/ArkUI 独立工程 | 独立后台应用与管理 API |
| 业务功能 | 我的、语聊/直播、私聊、通知、购买 | 同一业务规则，独立系统适配 | 同一业务规则，先完成 SDK PoC | 运营、审核、客服、财务、配置与审计 |
| 实时互动 | 当前定制八麦房与悬浮球基础 | 音频焦点、前台服务、厂商后台限制 | AVSession、持续任务、权限与生命周期 | 巡房/处置按角色授权，默认无主播权限 |
| 系统能力 | APNs、相册、蓝牙、音频中断 | 厂商 Push/FCM、通知权限、音频路由 | 鸿蒙 Push、相册、音频与任务管理 | MFA、短会话、权限隔离、防 CSRF/XSS |
| 付费 | StoreKit 与购买恢复 | 按发行渠道接支付/应用内购买 | 按鸿蒙渠道接 IAP | 查询、退款/调账审批，不直接改余额 |
| 权威判断 | 四类前端均只展示服务端确认结果；身份、处罚、价格、钱包和权益不能靠本地状态决定 | 同左 | 同左 | 所有管理请求仍由服务端鉴权与审计 |

共享 API、消息格式、设计规范和测试用例，不强求共享原生 UI。Android APK 的兼容运行不等于原生鸿蒙交付。官方已提供 [TRTC HarmonyOS SDK](https://cloud.tencent.com/document/product/647/130532) 和 [IM HarmonyOS API](https://cloud.tencent.com/document/product/269/103559)；[Live 平台表](https://intl.cloud.tencent.com/zh/document/product/647/60034)与 [RoomEngine 发布日志](https://cloud.tencent.com/document/product/269/125816)应结合阅读，不能推导当前 iOS 房间定制在鸿蒙完整等价可用。

## 共享 API 与事件契约

| 项目 | 建议契约 |
| --- | --- |
| 身份与资源 ID | 业务账户、房间、订单使用不透明字符串；显示 ID 可修改/绑定，不能代替权限判断；所有端点校验资源归属 |
| API 版本 | OpenAPI 作为合约；新增字段向后兼容，枚举有未知值兜底；破坏性变化开 `/v2`，维护最低客户端版本与迁移期限 |
| 金额 | `amountMinor` 用整数字符串，`currency=CNY` 时单位分；不传浮点元。虚拟币另用整数与独立单位，不能当人民币余额相加 |
| 时间 | 新协议统一服务端 UTC、Unix 毫秒并在字段标注；到期和交易时间由服务器判断。现有 `/v1` 使用秒，保留语义，不能静默改单位 |
| 幂等 | 充值、送礼、退款等带 `Idempotency-Key`；唯一约束为账号+操作+幂等键，另保存请求摘要校验同键异内容并拒绝；相同内容重复请求返回原结果，渠道交易号另设唯一约束，保留期覆盖渠道重试和业务追索 |
| 并发与分页 | 更新带资源 `version`，冲突返回可识别结果；列表使用稳定 cursor；钱包扣减依靠数据库事务与约束 |
| 错误码 | HTTP 表达认证/权限/冲突/限流等，业务码如 `ACCOUNT_BANNED`、`ROOM_ENDED`、`BALANCE_INSUFFICIENT`；带 `requestId`、是否可重试和重试间隔，不暴露堆栈/密钥 |
| 事件包 | `eventId/type/schemaVersion/aggregateId/aggregateVersion/occurredAt/traceId/payload`；按对象处理版本，不假设全局有序或只送一次 |
| 可靠投递 | 数据库事务写状态与 Outbox；消费者去重、重试、死信、补偿；只追加资金流水，纠错用冲正。客户端实时事件丢失后可重新查询权威状态 |

客户端上报设备、版本与能力仅用于兼容和诊断，不能据此授予权限。登录凭证、购买票据和敏感资料不进入埋点或访问日志。管理 API 与用户 API 分权限域，管理台不持有腾讯管理员密钥。

## 腾讯 SDK 适配与真实房间映射

产品层定义 `AccountService / RoomService / MediaSession / MessagingService / PushGateway`；腾讯类型和错误码集中在适配层。统一进退房、座位状态、设备路由、重连、房间结束和被踢事件，保留供应商诊断码用于排障。

目前代码直接使用带业务前缀的 Live ID。商用建议独立保存 `businessRoomId → provider + sdkAppId + liveId`；只有 SDK/官方接口确实提供时才记录底层 `rtcRoomId/groupId`，不能自行猜测内部映射后调用错误的管理 API。房间公开状态、审核/处罚与付费准入由业务库掌握，实时成员、麦位和媒体状态由云端同步；通过回调与定期校验处理异常退出和状态漂移。

UserSig 只作腾讯身份凭证，不代替业务 session。封号需撤销业务会话、停止签发并联动 IM 与 Live/媒体链路。[IM 登录态失效](https://cloud.tencent.com/document/product/269/3853)后，新签发 UserSig 仍可登录。[PrivateMapKey](https://intl.cloud.tencent.com/zh/document/product/647/35157?lang=zh)可做房间权限控制，但当前 Live 封装、鸿蒙接口与上下麦刷新链路是否完整适配必须 PoC；**不能直接打开控制台开关影响全部旧端进房**。

鸿蒙 PoC 使用三端真机和独立测试应用，至少验证：

1. 8 人含房主同时上麦，第 9 人留在观众；申请/邀请、锁麦、换麦和并发抢位后各端状态收敛。
2. 管理员禁麦、踢人、封禁、强制关房真正中断媒体；旧凭证重连不能绕过处罚。
3. 锁屏、退后台、悬浮返回、来电、蓝牙切换、抢占音频、进程被杀和网络切换均有明确行为。
4. 资料、房间消息、重复/乱序事件、重连恢复、长时间运行及实际计费用量可观察；支付/Push 分别完成渠道真机验收。

## 私聊、业务通知与 Push

三层分别设计：**IM 私聊**负责会话/消息与漫游；**业务通知库**保存处罚、申诉、订单、会员和系统通知及已读状态；**Push**只负责离线提醒和安全跳转。通知落库后异步投递，用户重新打开仍能查询，不能把推送到达当业务履约或已读证明。

房间历史不能套用旧的通用 IM 结论：[Live 当前文档](https://intl.cloud.tencent.com/zh/document/product/647/60034)已列出历史消息能力，[iOS 弹幕指引](https://intl.cloud.tencent.com/zh/document/product/1071/76783)说明控制台可配置新成员拉取消息。需核验当前版本、套餐、开关、条数、期限与消息类型；近期上下文不等于长期存档或举报证据库。

Push token 按账号、安装实例、平台、通道、环境和更新时间绑定；换号解绑、token 轮换/失效清理，重装不能继承前用户消息。iOS 使用 APNs；Android 按市场配置厂商通道/FCM；鸿蒙使用独立通道与签名配置，见 [官方通道回调](https://cloud.tencent.com/document/product/269/102568)。业务 session 放系统安全存储，不把 Push token 当登录凭证。

DeepLink 只接受白名单路由和参数；优先受验证的 HTTPS App Links/Universal Links 及对应平台链接能力。通知只携带对象 ID，打开后重新登录/鉴权、检查封禁与资源状态；禁止链接携带 Bearer、任意网页跳转、自动送礼或自动退款。锁屏文案默认隐藏敏感私聊内容。

## 支付验单与跨端权益

iOS 数字礼物/充值/会员按中国大陆商店规则采用应用内购买；Android 按各发行渠道规则接入，鸿蒙核验 [IAP Kit](https://developer.huawei.com/consumer/cn/sdk/iap-kit/)适配。具体可用商品和外部引导限制以 [Apple 3.1 支付规则](https://developer.apple.com/app-store/review/guidelines/#payments)及各渠道合同为准，不能统一展示“去网页低价充值”。

所有渠道均走服务器：核验签名/交易、应用/商户、环境、商品、金额、账号归属和唯一交易号→幂等订单→账本→交付；通知丢失主动查单补偿，退款/撤销追加冲正并更新权益。[App Store Server API](https://developer.apple.com/documentation/appstoreserverapi)提供交易、订阅及退款查询；客户端支付成功不直接加币。

会员权益绑定业务账户、保存来源渠道和期限，跨端使用遵守渠道规则；币钱包保留来源分账及消费限制，不能预先承诺全部充值余额无条件互通。禁止重复绑单、跨账号恢复购买和重复开会员；退款在所有端收回相应权益，客户端缓存过期重新查询。

## 云产品现状与供应商迁移成本

| 能力 | 当前可确认 / 需采购待核验 | 迁移成本与边界 |
| --- | --- | --- |
| Live/RoomEngine/TRTC | iOS 已链接并使用；实际授权、套餐、峰值及续费待核验 | **高**：房间、麦位、媒体和三端 SDK 需适配重测，不能只换域名 |
| IM 私聊与 Push | 当前房间消息链路已有；完整私聊/Push 未接，独立档位和通道待核验 | **中高**：用户映射、会话、消息历史、token 与厂商配置迁移 |
| 计算与关系库 | 已有单 Linux 服务和 SQLite；不能从 IP 认定具体云主机产品/规格 | **中**：迁往托管关系库需数据/事务校验；API 无状态后计算较易迁移 |
| 对象存储/CDN | 当前头像在服务器本地；COS/CDN、证据与录制桶未见接入 | **中**：对象搬迁、URL/权限、生命周期、缓存和出网成本；用存储适配器降耦合 |
| 审核/录制/回放 | 未见完整闭环，产品与额度均待核验 | **中高**：任务、回调、证据、保留规则及人工流程须重建 |
| Redis/MQ/负载均衡 | 未见商用部署证据；按 SLA 采购托管或自建 | **中**：协议兼容之外还需验证消息语义、持久化和故障恢复 |
| 监控/日志/安全/备份 | 健康检查、systemd、同机备份基础；异地副本、外部告警、WAF/DDoS、密钥管理待建设 | **低至中**：开放格式与独立副本便于迁移，安全策略和恢复演练需重验 |
| 短信/身份核验/支付 | 未接完整商用链路，主体资质、渠道合同和费用待核验 | **中高**：实名/商户迁移受合同限制，历史订单仍需原渠道退款与对账 |

采购按需求选型，不要求全部使用腾讯云。优先掌握自有业务 ID、资金账本、处罚和证据索引；记录供应商映射、配置版本、数据导出方式及退出预案。多供应商实时互通、云端历史迁移和同房间热切换均需专门建设，不能承诺适配器自动解决。
