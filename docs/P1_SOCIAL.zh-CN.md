## 服务和身份边界

`kiki.group / 43.138.219.160` 负责 Apple 业务账号、公开资料、关系、动态、私聊、站内通知及社交举报；`furby.top / 139.224.50.108` 继续负责 LiveKit 房间和语音，以及唯一的个人拉黑关系。运维 Passkey 与普通 Apple 用户不共用身份。

账号服务通过固定 `POST /internal/v1/account/social-policy` 获取未缓存的双向屏蔽快照，通过 `.../social-block` 更新同一份拉黑关系。两者使用已有独立 account-voice-v1 HMAC、精确路径和原始正文摘要、时间窗、共享持久一次性 nonce，并限制账号服务器源 IP。没有创建语聊用户的账号也可以设置拉黑，不伪造语聊会话。超过屏蔽列表上限直接拒绝服务，不截断而漏掉屏蔽项。

隐私策略不可达或格式不正确时，社交读写返回 503；登录、注销和撤回不会依赖该查询成功。语聊封禁不自动等同社交禁言，也不阻断 Apple 登录。社交禁言限制发动态、评论和私聊，不能代替语聊房间权限。

语音房间内拉黑仍主要影响本人接收音频／文字，不能阻止公开房间其他人收听。社交资料、动态与私聊使用双向隐藏；拉黑同时移除双方关注，不在解除拉黑后自动恢复关注。

## 安全、图片及数据保留

所有普通社交接口要求有效账号会话、当前成人协议同意和已完成昵称。公开资料只提供公开 ID、昵称、简介、头像和必要关系数据，不提供 Apple 标识。图片从系统选择器主动选取，App 与服务器缩小、转换为静态 JPEG 并剥离元数据。单图最多 2 MiB、动态最多三图；服务器还检查格式、尺寸及帧数，拒绝其他内容。

社交图片位于账号数据目录 `social-media/<UUID>.jpg`，目录 0700、文件 0600，所有读取需要认证及可见性检查。没有将该目录映射为公开静态文件；原公开头像目录不是社交图片存储。Ops 图片必须由未过期案件引用且具有 community 权限，不能任意浏览私聊或私有图片。客户端只有按账号隔离的内存图片缓存，退出、切号、撤回及拉黑变化清理；迟到请求不能恢复旧身份或被屏蔽内容。

| 数据 | 期限／限额 |
| --- | --- |
| 私聊消息 | 最长 30 天滚动保留；会话未读和历史不构成长久备份。 |
| 社交通知、本人举报、按需证据 | 最长 30 天。 |
| 操作审计和幂等回执 | 最长 90 天，避免重试重复处理。 |
| 未提交的上传图片 | 24 小时后清理；已删除内容无有效引用的图片随维护清理。 |
| 动态、评论、点赞、关注 | 功能所需期间保存；本人可删除动态／评论、取消关注；撤回和注销清理关联内容。 |
| 图片及发布配额 | 每人最多 200 条动态、600 张图片；另有日常请求及发送频率限制，具体值以 API 合约为准。 |

被举报并按需留存的图片可在前台内容删除后继续作为案件证据保存，最长 30 天。撤回和注销清理关联的在线社交关系、会话、内容、通知、举报与图片引用；另一参与者的在线会话也会被移除。既有受限备份、WAL 和用户已经取得的副本不是物理即时擦除。

写入使用数据库事务、服务器解析目标和请求 UUID 内容哈希。未知提交结果的私聊会复用原 UUID，不用新编号自动再发；明确的内容拒绝允许修改草稿。举报和管理处置同样幂等；运维未确认操作在原操作者 Keychain 中保留，即使关闭 App 或退出也不改编号重罚。语聊与社交的未确认操作使用不同存储键。

拉黑请求携带账号服务器注入的同意 epoch，撤回／注销及迟到请求沿用跨服务隐私水位；普通客户端不能自行选择 epoch 或替别人设置屏蔽。分页游标绑定身份、接口和筛选，用服务间密钥派生的独立用途密钥签名，不依赖退役腾讯密钥。

同一 Wi-Fi 下的已认证普通请求按有效数据库会话分别限频：每会话每分钟 180 次，已认证共享 IP 每分钟 6000 次；匿名、伪造、过期及已撤销凭据仍为每 IP 每分钟 240 次。登录、内部及运维入口不进入普通业务额度，保留既有保护；发送、上传等接口还执行自己的更严格规则。此调整属于请求保护修复，不是新承载测试。

## 消息左滑菜单（2026-10-20）

消息会话行使用系统原生 `swipeActions`：右侧红色删除、左侧紫色置顶，已置顶时切换为取消置顶，姓名旁显示图钉及浅紫底色。禁止一次完整左滑直接删除；删除前显示确认，明确仅清理自己这一侧。通知聚合在存在可清理历史时也有删除动作；无历史的通知入口保留打开和置顶。正常排序为置顶优先，再按最近活动排序；服务端先排序再分页，远处的置顶会话不会被当前第一页遗漏。

账号服务新增本人会话状态、通知状态及单调通知序列表。私聊清理只推进本人 `cleared_through_seq` 和已读水位，不删除另一参与者的消息；通知采用独立全局序列，不能用同秒随机 UUID 排序替代清除截止。操作固定用户确认时的最后内容 ID，确认期间或之后产生的新内容不会一并清除；新内容恢复会话，已清历史继续隐藏。旧请求复用原 UUID 与截止，不能重复清新内容或取消后来重新设置的置顶；UUID 大小写也统一处理。账号退出、重新登录与多设备访问沿用服务器状态。

客户端通过服务器水位过滤已缓存分页；后台旧响应、退出后的迟到成功和清理前的未读计数不能恢复记录或徽标。结果未确认时，重试保持同一 UUID 和截止，完成服务器确认后才清本地草稿；通知清理不影响私聊草稿。已清内容不参与未读、APNs 徽标或旧推送入口，运营删除导致的权威空历史页也会清除缓存。对方仍可在既有 30 天保留窗口访问自己的历史；该功能不是共享消息或受限备份的物理即时擦除。代码回滚时必须保留清除水位的读取过滤，不能用旧读取逻辑恢复已清的本人记录；不得回灌旧数据库覆盖上线后的状态。

## 动态条目与详情（2026-10-20）

## 首次联系额度与刷新稳定性（2026-10-20，本地待发布）

本轮私聊发送权限不再由关注关系决定。A 在 B 首次回复前最多发送 5 条文字，B 回复后双方可持续交流；B 可以回复达到上限的 A。服务端单个事务统一校验权限、计数、写消息、幂等回执和推送，失败／拒绝／重复 UUID 不重复消耗额度。第 6 条在尚无回复时返回 `direct_message_reply_required`，并附服务端发送状态。

`social_dm_contact_state` 保存双方已提交消息数量，私聊正文与会话可见性保持独立。历史双向消息在迁移时标为已回复；已有单向超过 5 条的历史不删除，但继续发送要等待回复。清空本人会话、正文 30 天过期、正常退出再登录以及取消关注均不重置限额。隐私撤回和注销按现有数据清理边界删除新增状态。拉黑、账号／会话失效及社区发布限制仍优先于私聊额度。

消息页、会话列表、发送回执提供 `canSend`、`remainingBeforeReply`、`requiresReply`、`replyEstablished` 和 `initialMessageLimit`。客户端以服务器为准；缺少新字段的旧服务继续使用其 `canSend`，不会本地假定可以发送。第 5 条成功和第 6 条拒绝立即更新输入权限，仍不确定的发送只用原 UUID 查回执，保留可编辑草稿。读取代次防止旧 GET 覆盖新回执或令已发送气泡消失。

私聊推送、徽标和点击解析同时移除互关要求，保留消息实际存在、发送者匹配、会话参与资格、本人清除水位、双向拉黑和治理校验。取消关注不再取消私聊 outbox；真正拉黑继续取消。前台推送只通知内容失效，再由 HTTPS 读取，不把推送正文作为聊天数据。

消息首页和私聊页面仅前台可见时做 15 秒低频补偿；推送、写操作及相关社交变化即时刷新。隐藏页面、房间覆盖、个人主页／举报弹层、后台与隐私退出暂停对应读取。静默刷新不显示 loading、不整体禁用输入或清空已有内容；消息首页首屏与分页共享读取入口，避免同时读导致游标与尾页回退。

本地协议资源同步准备为 r12，明确新增限额状态的用途及保留规则，r11 原文归档不变。账号后端最终完整 423 项、语聊后端最终完整 439 项通过；原有依赖环境缺少 `webauthn` 的启动失败日志保留，实际通过结果使用已配置的隔离测试环境。模拟器最终用例、截图与版本信息见 `experiments/livekit/validation/stable-refresh-dm-2026-10-20/`。本轮未部署生产服务、未发布网站或协议、未在真实账号中发送私信、未操作真机；线上启用需要配套部署两套后端和协议资源。

## 个人主页操作与黑名单（2026-10-20，1.0.7 本地待发布）

个人主页半模态的发私信、关注和更多共用一行底部操作栏，使用 UIKit 标准按钮和原生更多菜单。主页只保留一个二级弹层状态，避免多个 sheet 争用同一呈现节点；确认关注后立即应用服务端关系结果，计数等次要摘要异步合并，慢摘要不阻塞按钮。旧摘要不能覆盖刚提交的关注结果。

更多菜单提供举报和拉黑。继续复用现有账户 `/v1/social/blocks/{userID}` 与语音安全服务，不新增第二份黑名单。拉黑后立即清理已展示社交内容和私信缓存，现有服务端屏蔽规则负责后续私信、动态、通知、房间文字与音频。解除入口为“设置 → 隐私 → 社区安全、黑名单与我的举报 → 黑名单 → 解除”；解除不自动恢复关注。

本轮验收见 `experiments/livekit/validation/profile-room-ui-2026-10-20/`，包含真实半模态中的原生按钮事件、私信二级弹层呈现和布局截图。测试数据来自离线 API fixture，不向真实用户发送私信或执行真实拉黑。
