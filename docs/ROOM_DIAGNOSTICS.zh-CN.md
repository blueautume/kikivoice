# 房间错误与警告诊断

2026-10-19。面向 KikiTalk 正式 iOS 目标及独立 KikiVoiceOps；账号服务 `kiki.group` 与语聊服务 `furby.top` 保持分开。此次不调整承载上限、媒体参数或超时策略。

## 本次问题与证据边界

用户反馈 iPad 的“穷奇0000”进入“穷奇”创建的房间时，以及创建房间时曾出现超时，随后不再复现。检查现存业务记录及两端近期服务日志，能够核对这两个业务身份和房间登记，但旧系统缺少完整的操作、阶段与请求关联证据，不能确认那次超时的根因。

旧 iOS 网络层曾将 `URLError.timedOut` 转换成泛化错误，现已保留安全的超时分类。另发现创建流程在媒体成功后重复更新已经生效的房间状态，及历史同步失败可能使成功入房被显示为失败；已移除重复状态更新，历史同步异常改记独立警告。这些是已确认的实现问题，不等于已证明是本次用户反馈的原因。

语聊 API 共享锁及串行 SFU 调用可能造成排队，但本次未据此改变并发模型或声称已定位原因。下一次可依操作与请求编号区分账号授权、业务接口、凭证、媒体连接、状态同步及运行异常。

## 使用方式

- 在 Xcode 运行更新后的 KikiTalk 至 iPhone / iPad；旧安装包不能追补本次新增的客户端记录。用户主动取消操作不记作故障。
- 创建、入房报错会显示短问题编号；房内“连接与音频诊断”可复制最近完整事件编号。服务端另生成请求编号。
- 更新 KikiVoiceOps 后进入“语聊服务 → 问题记录”，按昵称或公开账号编号、严重程度、操作类型查询，可加载更早记录并打开详情。
- 概览显示近 24 小时错误事件、警告事件及涉及创建/入房的去重操作数量。一次操作可以有多侧证据，也可能仅有非致命警告；没有成功尝试分母，不把这些数量叫失败率。
- 当前经核对的“管理员”已有 `voice` 权限，无需新增授权。该页面只读，`community` 处置权和 `account` 看板权都不能替代 `voice` 查询权。

## 记录范围和可靠性

创建和入房从用户操作起使用同一随机 `attemptID`，跨账号授权、创建/凭证接口及媒体连接；每个事件有独立 `eventID`，服务器响应有 `requestID`。上报仅包含允许的操作、阶段、代码、严重程度、时间、耗时、HTTP 状态、房间编号、iOS/iPadOS、App/系统版本。服务端从认证身份补入公开账号编号及昵称。

错误原文、请求地址和请求正文、令牌、Apple 标识、IP、设备名称、房间标题、文字与音频正文不进入该结构化日志。SDK/系统正常运行日志是另一数据范围，不能将本功能描述为采集全部控制台输出。

设备的私有待报队列为 0600、排除系统备份，最多 100 条/7 天。网络恢复、前台、成功入房及有上限的退避重试会补报；退出、切换身份、撤回或注销清理。授权失效等待重新登录或前台恢复，不反复定时请求；无效/冲突事件丢弃，避免堵住队列。

客户端通过账号服务持久队列补报，即使首次语聊授权还未成功也可以留档。账号服务每 5 秒尝试投递，每次失败指数退避至最多 300 秒；正文最长 7 天，成功即清空正文，仅留 UUID 与内容哈希去重凭据。每账号每来源 60 条/小时、300 条/日、待投递最多 1000 条，全库最多 20000 行。

语聊服务保存最长 7 天/全局最近 10000 条；按时间和数量淘汰可能提前删除。客户端提交每用户 20 条/分钟、100 条/日；可信服务器证据使用独立 30 条/分钟、300 条/日额度。重复质量警告有设备端 5 分钟去重及服务端短窗口合并。不是无损、无限期日志，不用于证明“没有记录即未发生问题”。两条传输路径相同 UUID/内容只留一条，更换内容返回 409。

创建、凭证及状态 API 的失败由语聊服务器独立留档；账号换取语聊授权的失败由账号服务器独立留档。设备完全离线、未更新客户端、尚未取得账号授权或记录配额满时，上报可能延迟或不可用。账号和语聊服务同时不可达时，管理台无法实时看见设备本地待报事件。

撤回/注销清理在线事件和待报队列；短期授权水位和注销防重放记录拒绝迟到的旧事件。不通过记录诊断创建语聊业务身份或绕过同意、准入与权限检查。

## 固定接口

| 服务 | 接口 | 鉴权与用途 |
| --- | --- | --- |
| 账号 | `POST /v1/voice/incidents` | 普通用户会话和当前同意；持久待报 |
| 账号 | `POST /v1/voice/session` | 创建/入房传 `X-Kiki-Attempt-ID` 和 `X-Kiki-Operation`，响应 `X-Kiki-Request-ID` |
| 语聊 | `POST /v1/telemetry/incidents` | 有效语聊会话；直接提交备用路径 |
| 语聊 | `POST /internal/v1/account/incident` | 固定方法/路径/正文哈希 HMAC，唯一 nonce，仅账号服务器来源 |
| 账号 | `POST /admin/v2/services/voice/incidents/query` | Passkey 运维会话、实时检查 `voice` 权限，固定代理 |
| 语聊 | `POST /internal/admin/v2/incidents/query` | 专用 Ops HMAC 与来源限制，只读筛选分页 |

精确契约：[room-incidents-contract.json](../experiments/livekit/shared/room-incidents-contract.json)。查询按接收时间及事件编号倒序；游标过期返回 422，App 要求刷新，不能重复复用失效游标。App 在前后检查身份及权限，后台、退出、切服务或撤权后拒绝迟到的响应。

## 协议与发布验证

新诊断关联公开账号，协议资源升级 `2026-10-19-r4`，集合校验值 `15ee883b54d07295ef9a89c5fd3e05a7571a267c7015b3cb3ddd9cbb07bfc195`。App、两端 API、官网同步生成，旧版归档保留。App 隐私清单包含关联身份的 Performance Data 与 Other Diagnostic Data，均用于 App Functionality，不用于追踪。

发布前仍有 2 台设备在线，用户已明确允许本次中断当前测试语聊后立即发布。发布结果和公网验收记录位于 `experiments/livekit/validation/room-incidents-2026-10-19/`；最终状态以其中报告及本节后续验收记录为准。

## 最终验收结果

- 两端后端已发布并健康；语聊和账号源文件分别 11、13 个，与本地逐文件 SHA-256 核对一致。Nginx 语聊内部签名入口仍仅允许账号机来源，外部访问 403；官网四份正文、r4 归档与旧 r3 归档均可访问。
- 账号后端 306 项、语聊后端 319 项、备份 6 项通过。主 App 77 项执行（76 通过、1 既有可选公网集成跳过），Ops 49 项执行（48 通过、1 既有私密 WebAuthn 集成跳过），零失败。最终耗时文案的截图测试另 1 项通过。
- 两个 App 的 generic iOS 真机签名构建及 strict codesign 校验通过；团队 A82X46N3WS，Bundle ID 分别为 com.kikitalk.demo / com.kikitalk.voiceops。未安装至真人设备；需在 Xcode 重新运行更新后的 App。主端随包含 r4 和关联诊断的隐私清单。
- 公网临时身份验收 21 项通过，覆盖持久补报、双路径幂等、内容哈希冲突、严格字段、固定路径 HMAC 防重放、软件 Passkey、只读 voice ACL、404 服务端独立打点及请求编号、分页筛选、撤回/注销和迟到事件拒绝。所有临时账号、会话、诊断及待报队列核实清零。该验收没有真实 Apple 登录、没有创建媒体房间，也不替代真实设备的新打点人工复现。
- 真实“管理员”账号的 account / voice / community 三项授权仍在，本次没有修改其权限。
